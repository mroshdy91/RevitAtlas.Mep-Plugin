# Atlas MEP: admitted native project scope

Atlas MEP uses the shared Atlas Core runtime. Before authoring, read this installation's `RELEASE-READINESS.json`, confirm `mep_admission.scope_id` is `mep_native_v1`, and use its `actions`, `constraints` and limitations as the release boundary. An available tool or eligible native category does not by itself qualify every action, content type or engineering scenario. Read the current `atlas_catalog` contract for an admitted action when its inputs are needed. Atlas Family owns loadable-family authoring.

Start with `atlas_status` and the actual Revit 2025 or 2026 session. Create or open an owned standalone project through Core, capture the engineering brief with `atlas_requirements`, and inspect current levels, types, systems, symbols, phases, hosts and links. Workshared and cloud writes are outside this scope. Use discovered project identities, explicit units and current work revisions. A copied or historical connector handle is invalid after a model change; reacquire it from the current network inspection.

Use `atlas_mep_setup` to inspect project readiness and, only when admitted and authorized by the task, plan/apply/verify shared routing or system rules. `atlas_mep_routes` plans and builds admitted pipe, flex pipe, duct, flex duct, conduit and tray routes; use only route kinds declared in the live admission. Preview restores native construction and does not approve the design. Build a retained current plan, inspect committed fittings and endpoints, and distinguish native physical connections from touching geometry. Flex routes need explicit control points. A route type and system must resolve to the declared native kind and service.

Use `atlas_mep_elements` for admitted content loading, placement, connected movement, rotation, replacement, insulation and removal. Resolve a real supported category, host and connector domain first. Use `atlas_mep_connections` for admitted physical joins, branches, tees, inline work, caps and disconnections. Inspect dependencies and list only engineering-intended affected neighbours in `allowed_changes`; Revit may change adjacent fittings, system membership or calculated values. For replacement or edits, check exact existing peers, identity preservation and unrelated controls after mutation.

Use `atlas_mep_systems` for admitted mechanical or piping membership and native value changes. Use `atlas_mep_electrical` for admitted circuits, panels, loads, native circuit paths and panel-schedule content; verify exact circuit members and panel cells after editing. Conduit and tray routing does not prove an electrical circuit or wire. Use `atlas_mep_spaces` for admitted phase/level-aware spaces, zones and linked reconciliation. Shared setup and linked-model changes need their own declared scope and post-change verification.

Read Core MEP catalog, network, dependency, demand, preservation and panel-schedule inspections as relevant. Physical edges, logical systems, circuit membership and calculated demand are separate facts. Confirm assigned values and calculated downstream responses independently; a stored zero or enabled calculation setting does not prove a solved network. Use a restoring calculation-response check when the brief requires calculated flow. Validate measurable requirements and actual native identities, dimensions, peers, membership and parameter values. Missing or unsupported checks remain incomplete even if a tool call succeeded.

For drawing deliverables, use Atlas Sheets and Annotations when installed. Inspect actual schedule cells, native tag text and the captured view or sheet; a non-orphaned tag can still have an empty label. Save and reopen the RVT through Core delivery, then read back the required engineering state. Record task-specific design and visual review separately from connectivity validation. On a failed or uncertain mutation, inspect its committed, rolled-back or partial state and recover the original operation identity before continuing; do not replay an uncertain edit with a new identity.
